# Constraints

1. Never claim software certifies food safety.
2. Never automatically confirm recipient acceptance or delivery.
3. Human review is required before real-world handoff.
4. Do not contact external services or publish data without approval.
5. Never commit credentials, tokens, or secrets.
6. Back up `foodloop.db` before schema changes; never delete it as a first fix.
7. Update docs/tests when changing API fields or architecture.
8. Do not claim production readiness without security, privacy and partner validation.
9. Location is currently text; no distance calculation is implemented.
10. Use fictional demo data unless organisations have explicitly consented.
